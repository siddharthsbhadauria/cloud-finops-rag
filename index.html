What a million LLM tokens cost, and what you get for it

Every day a GitHub Actions job pulls current API prices for the top models from several providers via OpenRouter, checks them against a data contract, joins published MMLU scores and ranks each model in DuckDB by MMLU per blended dollar.

Method

How the numbers are made, so you can judge them.

Blended price
75% of the input price plus 25% of the output price, per million tokens. Most production workloads read far more than they write.
Value score
MMLU score divided by blended price. Higher means more benchmark quality per dollar. It ignores latency, context length and task fit, so treat it as a first filter, not a verdict.
Prices
Pulled daily from the OpenRouter models API, which lists per-token prices for each provider’s hosted models.
Quality scores
MMLU and throughput come from a hand-maintained table of published results. Models that aren’t in the table get an estimate from their size and context window; those rows are marked est. and left out of today’s picks.
Quality gate
A Python data contract checks every pull: required fields present, no negative prices, MMLU between 0 and 100. If it fails, the pipeline stops before anything is published.
Pipeline
GitHub Actions cron → OpenRouter API → data contract → DuckDB → JSON → GitHub Pages
